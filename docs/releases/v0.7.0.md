## Upgrade notes

### Usage-pause gate (#1944): set up the poller before you upgrade

`bin/hos-cron` now gates every worker and overseer cycle, for all projects on the host, on a Claude usage reading. At cycle start, before any network call, the cycle pauses when **session, weekly (all models), or any weekly per-model** usage is at or over its threshold (default 90 each), or when the reading is missing, stale or failed. It resumes on its own once usage drops. It keeps no state, files no GitHub issue, and is separate from `hos-suspend`. Interactive sessions are never paused.

The reading is written by a new poller, `bin/hos-usage-poll`, which runs from cron every 5 minutes and reads `/usage` under your personal login over SSH loopback. Setup is in `docs/CRON-SETUP.md` section 2a.

**An upgrade stops autonomous work until the poller is running.** A host that takes this release without setting the poller up pauses every cycle, fail-closed, with `[PAUSED-USAGE] reading_missing` (or `poller_not_installed` when there is no reading, no settings file and no key). There is no other off switch. Before the upgrade PR merges:

1. Set up the poller per `docs/CRON-SETUP.md` section 2a and run `bin/hos-usage-poll --check` until every item passes **except item 8**. Item 8 is expected to FAIL at this point ("no usage-pause gate ... upgrade it"), because the scheduled `hos-cron` is still the old, ungated copy, so `RESULT:` stays FAIL until after the merge.
2. After the merge and deploy, re-run `--check` and expect `RESULT: PASS` with item 8 green: it checks that every scheduled `hos-cron` copy (the Worker clone's and the Overseer clone's are different files) carries the gate. Re-check after every upgrade of any project on the host.

**Consumers billed by API key** have no subscription `/usage` to read, so `fail_mode=open` in `~/.config/hos/usage-pause.conf` is their only route. fail_mode=open without a running poller means no quota protection. Every cycle that runs this way writes one `cycle-usage-unchecked` audit event, so the gap is visible in the audit trail.

An invalid `usage-pause.conf` (a bad value, an unknown key or a duplicate key) pauses every cycle regardless of `fail_mode`; the cron log line names the key.

If you set `timeout_bin` in `usage-pause.conf`, its basename must be `timeout` or `gtimeout`, otherwise `--check` item 6b FAILs.
