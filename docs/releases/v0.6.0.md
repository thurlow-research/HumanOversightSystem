# v0.6.0 — Astro & JS Support

**Theme:** Give an Astro / JS-TS consumer the same deterministic signal density and stack depth a Django consumer gets today; harden worker/overseer governance surfaced during the build.

97 issues closed. Epic: #1029. Milestone drained 2026-08-12 (#1330).

---

## Headline: JS/TS and Astro are first-class stacks

Before this release, the 12-dimension signal layer was implicitly Django/Python-only: on an all-`.astro`/`.ts`/`.js` changeset every `PY_FILES`-gated validator skipped, so roughly half the scoring dimensions went dark, and there was no pack giving the base team JS/Astro idioms. A two-layer pack closes that gap — a generic `node` pack (reusable for future Next/SvelteKit work) plus an `astro` pack layered on it via `pack.toml requires = ["node"]`.

**Foundation**
- Language-aware `JS_FILES` routing in `run_validators.sh` — the root dependency every JS validator hangs off (S1)
- JS toolchain discovery helper, `ensure_node` (S2), and installer `pack.toml requires` DFS-closure resolution — net-new parsing, `hos_install.sh --pack astro` now pulls in `node` automatically (S3, D3)

**JS/TS validators** — six new validators giving JS/TS changesets the same signal density as Python:
- `complexity_metrics_js.py` — tree-sitter AST cyclomatic complexity, not eslint's rule or escomplex (S4, D4/D5)
- `function_metrics_js.py` — length/params/return-paths, `.astro` frontmatter/`<script>` extracted via regex fence scan (S5)
- `static_analysis_js.py` — semgrep with a vendored ruleset, sole engine for JS (not additive like Python/bandit) (S6, D6)
- `rn_calculator_js.py` — Risk Number, provisional: reuses Python's Dai et al. weights, explicitly flagged `"provisional-js-reuses-python-weights"` pending dogfood calibration data (S8, D7)
- `n1_detector_js.py` — fetch/await-in-loop heuristic, marked provisional pending dogfood data (S9, D8)
- hallucination-surface: npm ecosystem + `package.json` dependency-existence check (S7)

All new validators emit the shared `schema.py` envelope and are language-gated by file extension in the shared `validators/` directory, not pack-discovered (D10).

**Gates**
- `lint_check.sh` — eslint gate for JS/TS (S10)
- `type_check.sh` — `tsc --noEmit`, defers to S12 on Astro projects (S11)
- `astro_check.sh` — `astro sync` then `astro check`, not a build (S12, D9)

**Pack agent depth**
- `packs/node/` — base agent pack body, review-lens "find-the-defect" framing, spec-derived test independence (S13-S15)
- `packs/astro/` — same three layers on top of `node` via `requires` (S16-S18)

**Node/JS toolchain policy:** resolved from the consumer's own toolchain, never force-installed — `node_modules/.bin` → `npx --no-install` probe → PATH, floor Node ≥22, fail-hard preflight (D1, D2).

**AC-6 (dogfood field report) — waived at ship.** No field report from a real Astro project exists. Human decision 2026-08-12 (#1330): ship with AC-6 outstanding rather than block the release on it; a Tutelare field report, if it happens, files as a standalone issue against whatever milestone is active then and does not reopen v0.6.0.

## Governance & process hardening

A large share of this milestone was process-gap and governance work surfaced while building the Astro pack under the autonomous worker/overseer loop, not Astro-specific:

- **Canonical write/read scripts committed** — `bootstrap/create_issue.sh`, `submit_pr.sh`, `edit_issue.sh`, `query_issues.sh`, `post_comment.sh`, `revoke_app_token.sh` — closing the pattern where every issue/PR interaction hand-rolled its own `gh` + token-mint preamble (#1085, #1175, #1191, #1192, #1204, #1213)
- **Stale-base PR protection** — `submit_pr.sh` now merges from base before pushing, fail-closed on conflicts; closes the class of bug where a stale local branch silently proposed reverting already-merged work (#1162, #1166)
- **Worker throughput unblocked from serialized human merge** — `bin/hos-cron` is now the single decision authority for whether a cycle may pick new work vs. must fix an existing PR (#1198, #1230, #1236)
- **Validation-stamp gate repaired** three times in-milestone after regressions on `main` blocked all PR merges (#1323, #1333, #1367)
- **Overseer PR-review clarity** — every comment now leads with recommendation + expected action + what could not be checked (#1099, #1268); review-thread posting/resolution bugs fixed so findings are actually visible and gate merge (#1207, #1208, #1248, #1259, #1272)
- **Overseer merge-authority gates hardened** — protected-surface/CODEOWNERS check can no longer be skipped (#1325), human-authorized-merge idempotency (#1250), head-SHA freshness on the protected-surface bypass (#1251), defined signal source for the "security-relevant" gate (#1253)
- **Fail-honestly / fail-closed fixes** — validators no longer report "clean" when the underlying scanner failed to run (#1087); `run_validators.sh` tier-floor hoisting no longer masks a HIGH security floor (#1052); `validate_self.sh` no longer reports PASS when its reviewer invocation fails silently (#1362, #1365) — this fix is what let the release-validation gate below run for real for the first time and surface its own structural limits, rather than false-passing them
- **Model currency** — all 30 shipped agents were pinned to previous-generation model IDs; corrected (#1122)
- **Coverage/mutation scope gap** — the #314 shell→Python migration's own modules (including `merge_authority.py`) were excluded from coverage and mutation testing; fixed (#1174)
- **Token/credential handling** — `get_app_token.sh` callers no longer need to touch the token output file to verify a mint succeeded (#1086); a live token hand-copied into `settings.local.json` was found and flagged for manual removal (#1307)

## Upgrade notes

- **Pack install:** `hos_install.sh --pack astro` now resolves and injects `node` automatically via `pack.toml requires`; `--pack node` still installs standalone.
- **New validator dependencies:** the six JS validators need `tree-sitter`/`tree_sitter_typescript`, `semgrep`, and a discoverable Node ≥22 toolchain. None are force-installed — see `lib/detect_stack.sh` / `lib/resolve_node_tool.sh` for the discovery order. Missing tools are now caught in preflight rather than silently going inert (#1266).
- **Provisional signals:** the JS Risk Number calculator and N+1 analog reuse Python's calibration weights and are explicitly flagged provisional in their output — treat their scores as directional until dogfood data recalibrates them.
- **`hos_install.sh`**: re-run to pick up the `node`/`astro` packs and the committed canonical scripts above.

## Release validation — what ran, what didn't (NG3b Step R2, issue #1338)

v0.6.0 is the first HOS release to attempt an aggregate cross-vendor review at all — every prior release shipped with zero. It was cut under a human-authorized partial waiver rather than a clean 5-of-5 gate. Recorded here in full rather than absorbed silently:

**Green (deterministic, re-run at the cut SHA):**
- ✅ `run_tests_release.sh` — 2578 passed, 0 failed
- ✅ `check_agents_static.sh` — 0 findings
- ✅ `run_validators.sh` (diff since v0.5.0) — 12/12 validators succeeded, composite 0.6559 → tier HIGH

**Waived, with substitute evidence (human decision, 2026-08-14):**
- ⚠️ `validate_self.sh` (Opus self-review) — invocation fails on this release's diff size: `getconf ARG_MAX` (2,097,152 B) is exceeded by the 70-file, 2,028,660 B `.claude/agents`+`docs` changeset passed as a single CLI argument. Root-caused and filed as #1368 (fix: pass via stdin/file instead of argv — small, mechanical, not yet built). Accepted: suites below are sufficient evidence for this release; #1368 lands as a normal v0.7.0 follow-up.
- ⚠️ `run_second_review.sh` (cross-vendor second review) — failed identically 3 times in a row on the prior HEAD with the same diff-size structural cause (#1355), consuming ≈4.0M agy tokens (≈201% of the monthly plan allotment) and ≈3.2M codex tokens (≈644%) for zero signal. Withheld rather than retried a 4th time. **Waived** in favor of:
  - The existing per-PR second-review chain, which already covered all 18 S1–S18 build-step PRs individually before each merged.
  - A manual, hand-run chunked cross-vendor review of the full release diff (16 chunks ≤80KB each, strict risk order): **Tier 1** (7 chunks, 49% of source by size) completed 2026-08-13/14 — 13 of 14 agy/codex invocations produced a real review, 15 findings surfaced. Triage so far: 1 CRITICAL reproduced and disproven (false positive, a `set -e` semantics misread); of 5 further-verified HIGHs, 2 confirmed real and filed (#1369, #1380), 3 were false positives — notably all 3 false positives were agy's and both real findings were codex's, a useful vendor-reliability signal for future runs. Remaining HIGH/MEDIUM findings are individually tracked, unverified, see #1338. **Tier 2** (5 chunks) and **Tier 3** (agent/pack prose, lowest risk) were not run — a deliberate, quota-bounded stop, not an oversight.
  - `cut_release.sh`'s own internal validation gate (self-review + agy/codex semantic review over `.claude/agents`+docs) was likewise not run live for this cut — same ARG_MAX wall on the self-review half, and the same exhausted agy/codex quota on the other. The Tier 1 manual review above covers materially the same surface and is offered as substitute evidence for this gate too.

**Net:** every deterministic gate is green at the cut SHA. Both model-mediated gates were attempted for real — not silently skipped — and both hit the same understood structural bug (a release-spanning diff too large for a single CLI invocation) rather than surfacing a content finding. The manual chunked review supplies real cross-vendor signal in their place. Full evidence, calibration notes, and the open triage queue live on #1338 and its linked issues (#1355, #1362, #1368, #1369, #1380).
